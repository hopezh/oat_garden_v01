What “Projects” means across the Claude desktop app

A walk through the question, an initial answer, two rounds of verification, and the corrected conclusion about how Projects appears in Chat, Cowork, and Code.

Topic  Desktop app structure Tabs  Chat · Cowork · Code Verdict  Projects = Chat + Cowork
00

Overview

The Claude desktop app presents three tabs — Chat, Cowork, and Code. The conversation set out to pin down what the “Projects” item in the sidebar is, and how it connects to those tabs. Along the way, an early answer was corrected twice through verification against the documentation.

Bottom line

“Projects” shows up as a sidebar section in Chat and Cowork — but not in Code. The Chat and Cowork versions share a name but are distinct systems.

01

The question

The opening question was simple: What is the “Projects” entry in the desktop sidebar, and how does it relate to the Code section that sits alongside Chat and Cowork?

That turned out to hinge on an ambiguity — the word “project” is reused across surfaces with different meanings, so the honest answer depends on which tab's sidebar you're looking at.

02

The three tabs

All three run inside one app, but each is built for a different kind of work. Cowork and Code share the same underlying engine; Chat mirrors claude.ai.

Chat

Quick exchanges

The same Claude as claude.ai, plus native desktop extras: quick entry, screenshots, dictation, connectors.

Cowork

Sustained work

Research, analysis, and finished deliverables from many sources. Reads shared folders, runs scheduled tasks, spins up sub-agents.

Code

Building software

A development environment powered by Claude Code: full file-system access, terminal, visual diffs, and git.

03

Where “Projects” appears

This is the core finding. A navigable Projects section lives in two tabs, while Code has no such section at all.

ChatYes

Sidebar shows recent chats and Projects, exactly like claude.ai — workspaces that group chats with shared context.

CoworkYes

Its own Projects: group tasks with shared files, instructions, and memory so context carries between sessions.

CodeNo

The sidebar lists sessions. “Project” is only a per-session folder/repo attribute you can filter or group by.

Same word, different systems

Chat's Projects (claude.ai-style) and Cowork's Projects (files + instructions + memory) are separate features that happen to share a name.

04

How we got there

The final answer emerged through correction — a useful reminder to verify product claims against current docs rather than memory.

1

Initial answer overreached

It implied Code had a “Projects” concept comparable to the sidebar section. That framing was misleading.

2

Correction: Code has no Projects section

Verified in the Code docs — the sidebar lists sessions; “project” is just a session's folder/repo, usable as a filter or group-by dimension.

3

Verification: Chat does show Projects

Confirmed that the Chat tab mirrors claude.ai, whose sidebar includes Projects alongside recent chats.

05

How the tabs relate

  • Shared engine. Cowork and Code both run on Claude Code underneath — local, able to work independently, spin up sub-agents, and sustain long tasks.
  • Different scope. Cowork runs in a contained workspace limited to folders you share; Code runs directly in your project with full file-system, terminal, and dev-tool access.
  • Chat is the light surface. It's the claude.ai experience for quick back-and-forth, enhanced by desktop-native features.
06

Caveats

  • Rollout. The Code tab is still rolling out and may not appear for every user yet.
  • Plan requirements. Cowork and the Code tab require a Pro, Max, Team, or Enterprise subscription.
  • Verify, don't assume. Product features shift; conclusions here were checked against the official tutorials and Code docs.
07

Takeaways

If you see “Projects” in the sidebar

You're in Chat or Cowork — never Code. Check which tab is active to know which Projects system you're working with.

  • Chat Projects — claude.ai-style workspaces for grouping chats with shared context.
  • Cowork Projects — task groupings with their own files, instructions, and persistent memory.
  • Code — think in sessions, not projects; use the project filter to organize the session list.
