Git Worktree vs Branches

A practical guide to understanding when and why to use git worktrees alongside traditional branching.

Git Worktree Branching Workflow

What Is Git Worktree?

A git worktree lets you check out multiple branches of the same repository into separate directories simultaneously. Instead of one working directory that you switch between branches, you get multiple working directories — each on a different branch — all sharing the same .git history.

How It Works

Every git repository has a main worktree (the directory you cloned into). With git worktree add, you create linked worktrees — additional directories, each checked out to a different branch, that share the same object database and refs.

📁

Shared History

All worktrees share the same .git objects — no duplicated commits, blobs, or tags.

⚖️

Independent State

Each worktree has its own index, HEAD, and working files. Changes in one don't affect the other.

🚀

Zero-Cost Switching

Just cd between directories. No stash, no checkout, no rebuild.

🗑️

Easy Cleanup

Remove a worktree when done: git worktree remove <path>. That's it.

Disk Layout

~/ ├── myapp/ ← main branch (main worktree) │ ├── src/ │ ├── package.json │ └── .git/ ← the real git database (shared) │ └── myapp-hotfix/ ← hotfix branch (linked worktree) ├── src/ └── package.json ← linked back to myapp/.git

Key Differences

Branches and worktrees solve different problems. Branches are a logical tool for organizing parallel lines of development. Worktrees are a physical tool that gives each branch its own directory.

Git Branch Git Worktree
What it is A pointer to a commit A separate working directory checked out to a branch
Switching context git checkout — replaces files in place cd ../other-dir — files stay untouched
Uncommitted work Must stash or commit before switching Each worktree is independent, no stashing needed
Disk usage One copy of files One copy per worktree (shared .git objects)

Practical Example

Scenario: You're mid-feature on feature-x, and a critical production bug comes in that needs an immediate fix.

With Branches Only

# You're on feature-x, halfway through work
~/myapp (feature-x) $

# URGENT BUG! Save unfinished work
git stash

# Switch branch (all files change in place)
git checkout main
git checkout -b hotfix-bug

# Fix the bug, commit, push
git push

# Go back to your feature
git checkout feature-x
git stash pop          # pray there are no conflicts

# Wait for rebuild...

Pain Points

  • Must stash uncommitted work
  • All files are replaced on each switch
  • Full rebuild required twice
  • Stash pop can cause conflicts
  • Dev server must be restarted

 

Compare with the worktree approach below ↓

With Worktrees

# You're on feature-x, halfway through work
~/myapp (feature-x) $

# URGENT BUG! No need to touch anything here.

# Create a worktree in a separate folder
git worktree add ../myapp-hotfix -b hotfix-bug main

# Walk over to it (feature-x files untouched)
cd ../myapp-hotfix

# Fix the bug, commit, push
git push

# Go back — everything is exactly as you left it
cd ../myapp

# Clean up when done
git worktree remove ../myapp-hotfix

Advantages

  • No stashing required
  • Feature files completely untouched
  • Dev server keeps running
  • Only one build (the hotfix)
  • Zero risk of stash conflicts

Side-by-Side Summary

Key insight: Branches are free, but switching between them is not. Worktrees eliminate the cost of switching by giving each branch its own folder.

When to Use Each

Use Branches Alone When…

One thing at a time

You focus on a single task and context-switching is rare.

Switching is cheap

Small repo, fast builds — checkout takes seconds, not minutes.

Comfortable with stash

You're used to git stash and it fits your workflow.

Disk space matters

Each worktree duplicates the working files (though not .git objects).

Use Worktrees When…

Parallel branches

You need two branches open simultaneously — e.g., comparing behavior side-by-side.

Expensive rebuilds

Large repos where checkout + rebuild takes minutes. Keep both branches built.

Urgent interruptions

A hotfix lands mid-feature. Spin up a worktree, fix, push, resume with zero disruption.

Code review

Check out a PR in a worktree to test it without disturbing your current work.

TL;DR — Branches organize your work logically. Worktrees let you have multiple branches physically checked out at once so you never have to stash, switch, and rebuild.
