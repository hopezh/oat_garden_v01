Claude Code “ultracode”

The session switch that pairs xhigh reasoning with automatic, model-authored dynamic multi-agent workflow orchestration — what it is, when to use it, and how to configure it.

Compiled 2026-06-07 Method 5 research + 4 fact-check agents Model gate Opus 4.8 / 4.7 Requires Claude Code v2.1.154+
🛰️

This report was itself generated using ultracode — the background fan-out of 9 agents is exactly the dynamic-workflow orchestration that ultracode enables, so it doubles as a live demonstration.

01

What “ultracode” Is

Ultracode is a Claude Code setting — not a model/API effort level — that appears in the /effort menu. It does two things at once:

  • Sends xhigh reasoning effort to the model — the highest adaptive-thinking level the API exposes below max.
  • Grants standing permission for Claude to automatically orchestrate dynamic multi-agent workflows for substantive tasks.
Figure 1 — Ultracode = two things, one switch
The /effort one-liner — “xhigh + dynamic workflow orchestration” — is accurate.

The one precision worth knowing: the API’s actual effort scale is low / medium / high / xhigh / max. Ultracode isn’t a sixth API level — it’s a Claude Code behavior layer that pairs xhigh with an auto-orchestration permission.

📖

“Ultracode is a Claude Code setting rather than a model effort level: it sends xhigh to the model and additionally has Claude orchestrate dynamic workflows for substantive tasks.”

Behavior change

With it on, “Claude plans a workflow for each substantive task instead of waiting for you to ask… A single request can turn into several workflows in a row: one to understand the code, one to make the change, and one to verify it.”

Figure 2 — One request becomes a pipeline of workflows
Each phase runs as its own background workflow; only final answers return to context.

Under the hood

The “standing permission” is implemented via the Claude API’s mid-conversation system messages feature (Opus 4.8) — it grants standing consent to an expensive capability with a periodic refresher and an exit notice when you turn it off.

Constraints

  • Session-scoped — resets on a new session.
  • Model-gated — only offered on models that support xhigh: Opus 4.8 and Opus 4.7.
  • Research preview — dynamic workflows require Claude Code v2.1.154+.
02

Terminology & Relationships

One capability, one switch, one shared-but-overloaded word, and one impostor.

TermWhat it actually isRelationship to ultracode
Workflows / dynamic workflows The capability: a JavaScript orchestration script Claude writes on the fly that a background runtime runs, spawning subagents at scale (≤16 concurrent, ≤1,000/run). Intermediate results live in script variables; only the final answer returns to context. The machine. Normally opt-in (keyword, natural-language request, or a saved /workflows command).
Ultracode The switch that makes Claude author & run those workflows automatically, by default, for substantive tasks — plus xhigh. The “always-on” mode for the machine above.
“dynamic” (the word) Overloaded — two unrelated meanings (see below). —
Ultrawork ⚠️ NOT an official Anthropic feature. No relationship — it doesn’t exist in Claude Code.

About “ultrawork” — this premise was refuted

⚠️

“ultrawork” is not an official Anthropic feature. The /effort menu’s complete option set is low / medium / high / xhigh / max + ultracode + the per-turn keyword ultrathink. No “ultrawork.”

  • Third-party keyword — it comes from the oh-my-claude / oh-my-claudecode community ecosystem (e.g. TechDufus/oh-my-claude); aliases ulw/uw that hooks inject to force aggressive “never stop until done” parallel execution.
  • False dichotomy — the framing “ultrawork = general/non-coding, ultracode = coding” has no official basis. The only official orchestration setting is ultracode.
  • Likely point of confusion: ultrathink (official) — drop that word in a prompt to request deeper reasoning for that single turn without changing session effort.
03

Best Scenarios to Use It

Ultracode shines when the task is big enough that decomposition + parallelism + verification beats a single linear pass.

🔍

Codebase-wide audits

“Audit every endpoint for missing auth checks,” security/perf sweeps, dead-code hunts.

🔀

Large migrations / refactors

Fan out one agent per file/module with worktree isolation, transform, then verify each.

🧱

Multi-step features

The understand → design → implement → verify pipeline, each phase its own workflow.

📚

Deep research / fact-checking

Broad fan-out across sources with adversarial verification (the bundled /deep-research).

✅

Correctness checked

Adversarial verify, judge panels, completeness critics — not just produced, but proven.

Skip it for

Quick edits, single-file changes, conversational Q&A, anything latency-sensitive. The autonomy and token cost are pure overhead there.

04

Pros & Cons

✔ Pros

  • More exhaustive & correct — multi-agent decomposition + adversarial verification catches what a single pass misses.
  • Parallelism / scale — work exceeding one context window (≤1,000 agents/run) runs in the background while your session stays responsive.
  • Zero ceremony — Claude initiates workflows itself; no need to remember to ask.
  • Highest reasoning depth (xhigh) on every turn.

✘ Cons

  • More tokens & latency — docs are explicit: “each request uses more tokens and takes longer.” (This report spent ~390k subagent tokens across 9 agents.)
  • Can over-engineer — may spin up a workflow where a one-line edit would do.
  • Research preview — requires v2.1.154+, paid plan; behavior may change.
  • Less visibility — orchestration runs in the background (use /workflows to watch).
  • Model-gated — Opus 4.8 / 4.7 only.
  • Permission nuance — Auto mode skips the per-run prompt; Default/accept-edits may prompt per run unless you chose “don’t ask again.”
05

How to Configure It

Enable

# turn it on for the session
/effort ultracode
  • One-off without changing session effort — put the keyword ultracode in a single prompt:
    ultracode: audit every API endpoint under src/routes/ for missing auth checks
  • Programmatic — pass "ultracode": true via --settings or an Agent SDK control request.

Disable

# any normal level drops you out of ultracode
/effort high
  • Or just start a new session — it’s session-scoped and resets automatically.
  • There is no /effort off — you exit by picking another effort level.

Turn off the whole workflow machinery

(This also removes ultracode from the /effort menu.)

// ~/.claude/settings.json  (persists)
"disableWorkflows": true

# …or env var
CLAUDE_CODE_DISABLE_WORKFLOWS=1

# …or toggle "Dynamic workflows" off in /config

Related effort config (for context)

  • effortLevel in settings.json accepts only low/medium/high/xhigh — not max or ultracode (both session-only).
  • CLAUDE_CODE_EFFORT_LEVEL env var — highest precedence; the only way to persist max; does not accept ultracode.
  • --effort <level> launch flag; effort slider inside /model.
  • /config also has an “Ultracode keyword trigger” toggle (whether the literal keyword fires a workflow).

Bottom line

ultracode = xhigh + auto-orchestration of dynamic (model-written, multi-agent) workflows, session-scoped, Opus 4.8/4.7 only. “Workflows” is the engine, ultracode is the always-on switch, “dynamic” is an overloaded word with a second unrelated /loop meaning, and “ultrawork” is a community plugin keyword, not an Anthropic feature — most likely a mix-up with ultrathink (deeper reasoning for one turn).
