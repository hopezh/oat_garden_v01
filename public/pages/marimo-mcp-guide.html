Setup Guide

Connecting a marimo Notebook to Claude Code via MCP

Give Claude Code CLI live access to a running marimo notebook — cells, runtime state, and errors — over the Model Context Protocol. Two things must both be true: Claude Code needs the right address registered, and marimo must be actually running at that address.

📅 2026-07-06 ⏱ ~5 min read 🖥 Windows · macOS · Linux

TL;DR

  1. Add the extra and register the endpoint with a real port number, not the literal word PORT:
    uv add "marimo[mcp]" · claude mcp add --transport http marimo http://localhost:2718/mcp/server
  2. The MCP endpoint is served by the running marimo process — start it with uv run marimo edit … --mcp --no-token -p 2718.
  3. Then run /mcp in Claude Code to connect. Pin the port so the address always matches. No marimo running = nothing to connect to.

Overview

marimo can expose a running notebook server as an MCP (Model Context Protocol) server over HTTP.1 Claude Code CLI attaches to that endpoint as an MCP client,2 gaining notebook-aware tools (read cells, inspect runtime data, see errors) and ready-made prompts — without copy-pasting notebook state into the chat. Getting it connected has exactly two moving parts, and confusion usually comes from treating them as one.

The mental model — one idea to hold onto

The marimo MCP server is not a separate background service. It is served by the running marimo edit process. The --mcp flag simply tells that process to expose a /mcp/server endpoint on its own port.1

Consequence "Installed correctly" only means Claude Code knows where to look. If marimo isn't running there, the address points to nothing and /mcp shows it disconnected — no matter how correct the registration is.

Setup — four steps

Steps 1 and 2 are one-time; steps 3 and 4 repeat each working session. The setup assumes a uv-managed project with notebooks under notebooks/ — adapt paths as needed.

1

Add the MCP extra to the projectonce

marimo's MCP server needs the mcp optional dependency:1

uv add "marimo[mcp]"

This changes the existing marimo entry in pyproject.toml to marimo[mcp] and installs the extra — same marimo version.

2

Register the server with Claude Codeonce

The transport is HTTP, the name is marimo, and the URL points at the endpoint marimo will serve:

# registers the address in Claude Code's config
claude mcp add --transport http marimo http://localhost:2718/mcp/server

Scope choice: by default this lands in your local, per-project, private config. Add --scope project to write a .mcp.json into the repo instead, so the registration travels to other machines via git.2 See Configuration for the exact URL pitfall to avoid.

3

Launch the notebook via uv, on a pinned portper session

With the address registered, something must actually listen there. Start marimo through uv run so it uses the project environment, with the MCP endpoint enabled and the port pinned:

uv run marimo edit notebooks/notebook.py --mcp --no-token -p 2718
Tip Because this is a long-running, interactive process, you can launch it from inside a Claude Code session by prefixing with ! — its output then lands directly in the conversation: 
! uv run marimo edit notebooks/notebook.py --mcp --no-token -p 2718
4

Connect the sessionper session

Start a new session, or run /mcp in the current one to connect and check status. You then get:

  • Tools — marimo's notebook tools appear as mcp__marimo__*
  • Prompts — two slash commands: /mcp__marimo__active_notebooks and /mcp__marimo__errors_summary

!The PORT pitfall

In documentation you'll often see the URL written as http://localhost:PORT/mcp/server. The word PORT is placeholder notation for "your actual port number" — not a literal you register. claude mcp add stores the URL verbatim; nothing ever substitutes it. Registering it literally is exactly what produces this error:

Failed to reconnect to marimo: 'url' is not a valid URL: "http://localhost:PORT/mcp/server".
Update the server's config and reconnect.

Because http://localhost:PORT/… is not a parseable URL, Claude Code rejects it outright.1 Swap PORT for 2718 (marimo's default port3) and the URL becomes valid:

Do not claude mcp add … http://localhost:PORT/mcp/server  — the literal word breaks parsing.
Do claude mcp add … http://localhost:2718/mcp/server  — a real port number.

Where the registration is stored

The command writes an entry into Claude Code's per-project config file. You can also fix a bad URL by editing it directly — find the marimo entry under mcpServers and change :PORT to :2718:

"mcpServers": {
  "marimo": {
    "type": "http",
    "url": "http://localhost:2718/mcp/server"
  }
}

The config file lives in your home directory:

%USERPROFILE%\.claude.json
# e.g. C:\Users\<you>\.claude.json
~/.claude.json
# e.g. /Users/<you>/.claude.json
~/.claude.json
# e.g. /home/<you>/.claude.json
Note The claude mcp add command and the manual edit are equivalent — do one, not both. Running the command again just overwrites the entry with the same value.

What each launch flag does

Port pinning — why -p 2718 matters

marimo uses 2718 by default, but if that port is busy it silently picks another one (2719, …) — and then the address you registered points nowhere.2 Dropping -p 2718 mostly works by luck: a bare launch usually lands on the default. The catch is that a port conflict (a second notebook already open, a stale marimo process) breaks the MCP connection with no obvious error — marimo runs fine while Claude Code reports "disconnected."

Since the registered URL is hard-coded to 2718, pin marimo to it with -p 2718. That forces marimo to either use 2718 or fail loudly at startup, where you can see and fix it.

Strategy comparison

StrategyVerdictTrade-off
-p 2718 explicit, register 2718 Recommended Failure is loud: a port conflict surfaces at marimo startup, where you can see and fix it.
No -p, register 2718 Fragile Works until the default port is busy; then the port shifts silently and you debug a mystery disconnect.
${MARIMO_PORT} in a project-scoped .mcp.json Ceremony Claude Code expands ${ENV_VAR} in .mcp.json,2 but you must export the variable to match whatever marimo picked before each session — more effort than pinning, no real gain.
Keep them in sync The launch flag and the registered URL must name the same port. If you ever change one to a new port, change both. Bottom line: one fixed port, both sides agree, nothing to remember.

The session loop

Every working session follows the same three beats. The endpoint disappears when marimo closes, so this repeats each time.1

Available tools & prompts

Once connected, marimo exposes its notebook tools through the MCP interface (reading cells, runtime data, errors, and the rest of its AI-tool surface), namespaced as mcp__marimo__* in Claude Code.1 Two prompts ship with the server and surface as slash commands:

Slash commandWhat it does
/mcp__marimo__active_notebooksGet current active notebooks with their session IDs and file paths
/mcp__marimo__errors_summaryGet error summaries for all active notebooks

Troubleshooting

SymptomCauseFix
'url' is not a valid URL Literal PORT left in the URL Replace with 2718
/mcp shows disconnected marimo isn't running with --mcp Launch marimo, then re-run /mcp
Was working, now dropped Port 2718 was busy; marimo drifted Free 2718 or pin both sides to a new port
Remember A "disconnected" status when marimo isn't running is expected, not a config error. Start marimo first, then reconnect.

Caveats

  • Server lifetime: the MCP endpoint exists only while marimo edit is running. Start marimo first, then the Claude Code session — otherwise the marimo entry shows as disconnected.
  • Security: --no-token is acceptable only because the server is localhost-only. Don't use it if you ever expose the port.
  • Proxies / custom domains: marimo has a --mcp-allow-remote flag for DNS-rebinding-protected setups behind proxies1 — not needed for plain local use.
  • Long-running launch: marimo edit occupies its terminal; run it in a separate terminal tab from your Claude Code session.
