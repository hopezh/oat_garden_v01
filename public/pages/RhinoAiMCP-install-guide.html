Installing RhinoAiMCP Globally for Claude Code

A step-by-step plan to register the Rhino-hosted MCP HTTP server as a global, user-scope tool — available in every project, with verification and one-line rollback.

TL;DR

RhinoAiMCP embeds an HTTP MCP server inside Rhino at http://localhost:3001/mcp.[1] Claude Code speaks HTTP transport natively, so it installs globally in one command — no mcp-remote bridge required.

  • One command: claude mcp add --transport http --scope user rhinoceros3d http://localhost:3001/mcp
  • Scope: --scope user = global, available across all projects.
  • Catch: the endpoint only exists while Rhino is open and the RhinoAiMCP command is running.[1]
  • Rollback: claude mcp remove --scope user rhinoceros3d

Overview

RhinoAiMCP is a lightweight Rhino 3D plugin that embeds a local MCP (Model Context Protocol) server directly into Rhino, enabling bidirectional communication between your modeling session and local AI assistants.[1] The official instructions target Claude Desktop via an npx mcp-remote bridge; Claude Code can connect to the same endpoint directly over HTTP.

Rhino-side setup (manual — done by you, in Rhino)

A

Install the plugin

In Rhino 8: Tools → Package Manager, search "RhinoAiMCP", install, then restart Rhino. (Windows only.)[1]

B

Start the server

In Rhino's command line, run RhinoAiMCP. Confirm you see:

MCP server started: http://localhost:3001
Note: Registration in Claude Code does not require the server to be live — but using it does. If Rhino is closed, Claude Code will show the server as unavailable. That's expected, not a misconfiguration.

Step-by-step install plan

These are the exact commands I would run. Nothing executes until you approve.

1

Register the server globally

Direct HTTP transport, user scope (= global, every project). Writes to your global config.

claude mcp add --transport http --scope user rhinoceros3d http://localhost:3001/mcp
  • --scope user → global config, available in all projects.
  • --transport http → talks straight to the endpoint, no npx bridge.
  • rhinoceros3d → the server name (matches the source doc; renamable).[1]
2

Verify it's registered

claude mcp list
claude mcp get rhinoceros3d

list should show rhinoceros3d with its HTTP URL; get confirms scope = user. This works even with Rhino closed.

3

Verify the live connection

With Rhino open and RhinoAiMCP running, inside a Claude Code session run /mcp to confirm the server shows connected and lists its tools. If Rhino is closed, it shows failed — expected.

4

Confirm and report

I'll show you the final config entry and connection status, and note that the server only works while Rhino is running with the plugin active.

Reminder: Claude Code loads MCP servers at session startup. After registering the server, start a new Claude Code session (quit and relaunch claude) for the rhino server to appear under /mcp — it will not show up in a session that was already running when it was added.

Fallback — the mcp-remote bridge

If direct HTTP fails to connect (some plugins use a quirky SSE/HTTP handshake), re-add using the bridge from the official instructions, which routes through your installed npx:[1]

claude mcp remove --scope user rhinoceros3d
claude mcp add --scope user rhinoceros3d -- npx mcp-remote http://localhost:3001/mcp

Rollback

Removing the global registration is a single command:

claude mcp remove --scope user rhinoceros3d
