Publishing a Dash App to Plotly Cloud with Invite-Only Viewer Access

How a Dash dashboard was deployed to Plotly Cloud and how to lock it down so only invited users can view it — including the real terminal session.

TLDR
  • Install the cloud extension (uv add "dash[cloud]"), log in with plotly user login, and deploy with plotly app publish --name <app-name> — the app goes live at https://<app-id>.plotly.app.[1][2]
  • Published apps are private by default; access is managed in the app's Settings → Sharing tab on Plotly Cloud.[3]
  • For invite-only viewing: set Anyone with the link to No access and add specific people with Can view permission.[3]
  • Caveat: per-person sharing requires a Pro plan or higher; the free tier only offers all-or-nothing link sharing.[3][5]

Why Plotly Cloud

By default a Dash app runs on localhost and is only reachable from the developer's machine. Sharing it requires deploying to a server. Plotly offers two hosting platforms: Plotly Cloud and Dash Enterprise.[1]

Plotly Cloud vs Dash Enterprise

Plotly CloudDash Enterprise
InfrastructureFully managed by Plotly — nothing to set upSelf-hosted, full control
Getting startedFree plan availableLicensed installation
Best forSharing apps quicklyOrganizations needing full infrastructure control, LDAP/SAML, job queues, app portals

Switching between the two later usually requires no app-code changes.[1] This guide uses Plotly Cloud.

Publishing to Plotly Cloud

Prerequisites

Create a free account at cloud.plotly.com, then add the cloud extension to the project. In a uv-managed project:[2]

terminal
> uv add "dash[cloud]"

(In a plain pip project: pip install "dash[cloud]".)

Method A — publish from dev tools (in-browser)

Run the app with app.run(debug=True). The dev-tools panel that appears in the browser includes a publishing UI: select Plotly Cloud → Sign In, authenticate in the browser tab that opens, name the app, pick a team, and select Publish App. When the build finishes you'll see an App is live message.[1]

Method B — publish from the CLI

The CLI route (used in the session below) needs two commands:[2]

terminal
> uv run plotly user login
> uv run plotly app publish --name <app-name>

Login opens a browser device-authorization flow; credentials are stored locally and reused. For CI/CD, an API key via PLOTLY_API_KEY can replace interactive login.[2] Members of multiple teams can target one with --team <team-name> (list teams with plotly user teams).

plotly-cloud.toml

The first publish writes a plotly-cloud.toml into the project directory recording the app's name, app_id, and app_url. Commit it to version control — it is how subsequent plotly app publish runs (and collaborators or CI) update the same app in place instead of creating a new one.[2]

Size limits & URLs

  • Total app files must be under 200 MiB when publishing from dev tools/CLI (80 MiB when uploading directly at cloud.plotly.com). Data files the app reads at runtime must be included.[1]
  • Files matched by .gitignore (and things like virtual environments) are excluded from the upload automatically.[1]
  • The first publish assigns a UUID subdomain (https://<uuid>.plotly.app). Human-readable custom URLs require a paid plan: edit app_url in the TOML and re-publish.[2]

Sharing with Invited Viewers Only

Permission levels

Published apps are private by default — only the publisher can open the URL.[2] Access is managed per app in Settings → Sharing on cloud.plotly.com, with three permission levels:[3]

PermissionOpen the live app URLManage the app (Settings)
No access✗✗
Can view✓✗
Can edit✓✓ (Creator team role only)

Invite-only setup

To make the app viewable by invited users and no one else:

  1. Open the app's Settings → Sharing tab on cloud.plotly.com.
  2. Set Anyone with the link to No access — this is what keeps the bare URL locked down.
  3. Under Add specific people, search each person by name and add them; they land in the People with access list with Can view permission.
  4. If someone isn't in the team yet, select Send invitation to invite them (subject to the plan's team-member limits).
  5. Use Copy link to app to send the URL — Plotly does not email users when an app is shared with them.[3]

Invited users must sign in to Plotly Cloud to open the app — that sign-in is what enforces the access control.

Free vs Pro caveat

⚠ Plan requirement: giving access to the team as a whole or to individual people requires a Pro team plan or higher.[3][5] On the free tier the only sharing lever is Anyone with the link → Can view — an unlisted public link, not true invite-only access. For genuinely restricted viewer-only sharing: upgrade to Pro, add each viewer individually with Can view, and leave link access at No access.
