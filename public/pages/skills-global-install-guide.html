Where does “global” install with two config dirs?

Installing Matt Pocock’s skills lets you pick project or global. With two config folders in play, “global” is not one fixed place — it follows an environment variable. Here is exactly where it lands, and how to cover both.

TL;DR

The skills CLI resolves Claude Code’s global directory as <claudeHome>/skills, where claudeHome = CLAUDE_CONFIG_DIR || ~/.claude. It does respect CLAUDE_CONFIG_DIR — the README just never mentions it.[3]

Your variable currently points at ~/.claude-orion, so “global” lands in ~/.claude-orion/skills — not ~/.claude/skills. To also cover ~/.claude-work, run the installer a second time with the variable overridden.

Where “global” goes

rule 01 · follows the env var

The installer offers two scopes. Project writes to .claude/skills in the current repo. Global writes to a per-agent global directory. For the claude-code agent that global directory is defined in the CLI source as:[3]

// dist/cli.mjs — resolved once at startup
const claudeHome = process.env.CLAUDE_CONFIG_DIR?.trim() || join(home, ".claude");

// agent definition for Claude Code
"claude-code": {
  skillsDir:       ".claude/skills",      // project scope
  globalSkillsDir: join(claudeHome, "skills"), // global scope ← follows the env var
}
→

So “global” is not hard-wired to ~/.claude. When CLAUDE_CONFIG_DIR is set, that value wins; the ~/.claude default only applies when the variable is unset.[4]

How the path resolves

rule 02 · one branch
You choose npx skills add …  —global  —agent claude-code
│
CLI computes claudeHome CLAUDE_CONFIG_DIR  ??  ~/.claude
│
If var is SET (your case)
$CLAUDE_CONFIG_DIR/skills
If var is UNSET (default)
~/.claude/skills
│
Resolved for you now ~/.claude-orion/skills

Install into both configs

rule 03 · one run per dir

Each run targets exactly one config dir — whatever CLAUDE_CONFIG_DIR points at when the command executes. To cover both, run the installer twice, overriding the variable for each run. The npx skills add command itself is identical everywhere; only the way you set the variable differs by OS.

# override the var just for each run, then install globally
$env:CLAUDE_CONFIG_DIR = "$HOME\.claude-orion"; npx skills@latest add mattpocock/skills -g -a claude-code -y
$env:CLAUDE_CONFIG_DIR = "$HOME\.claude-work";  npx skills@latest add mattpocock/skills -g -a claude-code -y
# inline env prefix scopes the var to that single command
CLAUDE_CONFIG_DIR=~/.claude-orion npx skills@latest add mattpocock/skills -g -a claude-code -y
CLAUDE_CONFIG_DIR=~/.claude-work  npx skills@latest add mattpocock/skills -g -a claude-code -y
# inline env prefix scopes the var to that single command
CLAUDE_CONFIG_DIR=~/.claude-orion npx skills@latest add mattpocock/skills -g -a claude-code -y
CLAUDE_CONFIG_DIR=~/.claude-work  npx skills@latest add mattpocock/skills -g -a claude-code -y

The flags

  • →-g, --global — install to the user (global) directory instead of the project.[2]
  • →-a claude-code — target the Claude Code agent explicitly, so the run doesn’t prompt you to pick one.
  • →-y, --yes — skip all confirmation prompts, making the two runs non-interactive.

Drop -a and -y if you’d rather answer the scope and agent prompts interactively — the scope prompt is exactly the “project vs global” choice you mentioned.

Notes & caveats

before you run

Per-repo setup step

Matt’s skills expect /setup-matt-pocock-skills to be run once per repository (issue tracker, triage labels, docs location).[1] That’s project-side configuration, independent of which global config dir holds the skills — installing globally into both dirs doesn’t change that this step is per-repo.

Env-var scope

Setting the variable in a shell session only affects that session. Since it’s already pointing at ~/.claude-orion, that’s presumably your machine default (a persistent user variable). The two commands above temporarily override it for each install and won’t disturb that default — a fresh shell still starts on ~/.claude-orion.

Plugin alternative

If you’d prefer a read-only, auto-updating bundle over editable copies, the plugin route installs under the active CLAUDE_CONFIG_DIR too, so the same two-run pattern applies:[1]

# run once per config dir (override CLAUDE_CONFIG_DIR the same way as above)
claude plugin marketplace add mattpocock/skills
claude plugin install mattpocock-skills@mattpocock
ⓘ

Sanity check after installing: confirm the skill folders exist under each dir — ~/.claude-orion/skills and ~/.claude-work/skills — then restart Claude Code so it re-scans skills.
