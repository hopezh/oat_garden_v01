1.1  Multi-Page App Architecture (Dash Pages API)

▼
Sourcedash.plotly.com/urls — official, versioned
VersionPages API introduced in Dash 2.5; current stable: Dash 4.1.0 (2026-03-23)
CaveatsNone — Pages API is mature and well-documented
Next stepScaffold a /pages directory structure in the project
Key findings
  • Pages are .py files in a /pages directory; each calls dash.register_page(__name__) and defines a layout variable or function
  • Main app.py sets app = Dash(__name__, use_pages=True) and places dash.page_container in the layout
  • Routing auto-generated from module names (e.g. analytics.py → /analytics); override with path='/'
  • Dynamic URL segments: path_template="/report/<report_id>" passes variables to the layout function
  • All pages available in dash.page_registry (an OrderedDict)
  • Redirects via redirect_from=["/old-path"]; custom 404 via not_found_404.py in /pages
  • Page ordering: use the order parameter; unordered pages sort alphabetically

1.5  Dash Callbacks & Clientside Callbacks

▼
Sourcebasic-callbacks · clientside-callbacks
VersionDash 4.1.0; Promises since 2.4; Patch since 3.3; set_props since 2.16
CaveatsClientside callbacks block the browser's main thread — avoid heavy computation
Next stepUse Python callbacks by default; add clientside callbacks for high-frequency UI updates
Python callbacks
  • @callback(Output(...), Input(...), State(...)) decorator pattern
  • Multiple inputs and outputs per callback; chained callbacks supported
  • Unit testing (Dash 2.6+): import and call callback functions directly — no browser needed
  • Never modify global variables inside callbacks — causes multi-user state corruption
Clientside callbacks
  • Run JavaScript in the browser; eliminate server roundtrips for frequent/large-data callbacks
  • Inline JS string or external .js in assets/ via window.dash_clientside
  • Async support: return a Promise (Dash 2.4+) · Partial updates: dash_clientside.Patch (3.3+)
  • Direct component updates: set_props(id, props) (Dash 2.16+)

1.6  Claude.ai Integration via Anthropic SDK

▼
Sourceplotly/dash-ai-chat-tutorial (official) · PyPI: anthropic
Versionanthropic SDK 0.104.1 (2026-05-22); Python ≥3.9; MIT
CaveatsNo built-in streaming in standard callbacks; use SSE or polling for streaming responses
Next stepUse plotly/dash-ai-chat-tutorial as reference; wire Claude via Python callbacks
Key findings
  • Official Plotly tutorial integrates Claude, Gemini, and ChatGPT into a single Dash app
  • Stack: dash, dash-mantine-components, anthropic, dash-iconify
  • Recommended models (2026): claude-opus-4-7, claude-sonnet-4-6, claude-haiku-4-5-20251001
  • Install: uv add anthropic · API key: ANTHROPIC_API_KEY env var
Integration pattern 
import anthropic
client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from env

@callback(
    Output('response', 'children'),
    Input('submit', 'n_clicks'),
    State('prompt', 'value')
)
def call_claude(n_clicks, prompt):
    response = client.messages.create(
        model="claude-opus-4-7",
        max_tokens=1024,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.content[0].text
