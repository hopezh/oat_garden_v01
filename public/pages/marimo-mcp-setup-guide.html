Setup Guide

Connecting the marimo MCP Server to Claude Code

Two things must both be true for the connection to work: Claude Code needs the right address registered, and marimo must be actually running at that address. Here is how to get both.

📅 2026-07-06 ⏱ ~5 min read 🖥 Windows · macOS · Linux

TL;DR

  1. Register the server with a real port number, not the literal word PORT: claude mcp add --transport http marimo http://localhost:2718/mcp/server
  2. The MCP endpoint is served by the running marimo process — start it with uv run marimo edit … --mcp --no-token -p 2718.
  3. Then run /mcp in Claude Code to connect. No marimo running = nothing to connect to.

Overview

The marimo MCP server lets Claude Code read and act on the state of a live marimo notebook session. Getting it connected has exactly two moving parts, and confusion usually comes from treating them as one.

The one idea to hold onto

The marimo MCP server is not a separate background service. It is served by the running marimo edit process. The --mcp flag simply tells that process to expose a /mcp/server endpoint on its own port.1

Consequence "Installed correctly" only means Claude Code knows where to look. If marimo isn't running there, the address points to nothing and /mcp shows it disconnected — no matter how correct the registration is.

1Install the marimo MCP

Register the server once with the claude mcp add command. The transport is HTTP, the name is marimo, and the URL points at the endpoint marimo will serve:

# run once — registers the address in Claude Code's config
claude mcp add --transport http marimo http://localhost:2718/mcp/server

The PORT pitfall

In documentation you'll often see the URL written as http://localhost:PORT/mcp/server. The word PORT is a placeholder — you must replace it with a real port number. Registering it literally is exactly what produces this error:

Failed to reconnect to marimo: 'url' is not a valid URL: "http://localhost:PORT/mcp/server".
Update the server's config and reconnect.

Because http://localhost:PORT/… is not a parseable URL, Claude Code rejects it outright.1 Swap PORT for 2718 (marimo's default port3) and the URL becomes valid:

Do not claude mcp add … http://localhost:PORT/mcp/server  — the literal word breaks parsing.
Do claude mcp add … http://localhost:2718/mcp/server  — a real port number.

Where the registration is stored

The command writes an entry into Claude Code's per-project config file. You can also fix a bad URL by editing it directly — find the marimo entry under mcpServers and change :PORT to :2718:

"mcpServers": {
  "marimo": {
    "type": "http",
    "url": "http://localhost:2718/mcp/server"
  }
}

The config file lives in your home directory:

%USERPROFILE%\.claude.json
# e.g. C:\Users\you\.claude.json
~/.claude.json
# e.g. /Users/you/.claude.json
~/.claude.json
# e.g. /home/you/.claude.json
Note The claude mcp add command and the manual edit are equivalent — do one, not both. If you've already corrected the URL, running the command again just overwrites it with the same value.

2Launch the notebook via uv

With the address registered, something must actually listen there. Start marimo through uv run so it uses the project environment, with the MCP endpoint enabled and the port pinned:

uv run marimo edit chapters/p1_c01_01_make_sure_things_work.py --mcp --no-token -p 2718
Tip Because this is a long-running, interactive process, launch it from inside a Claude Code session by prefixing with ! — its output then lands directly in the conversation: 
! uv run marimo edit chapters/p1_c01_01_make_sure_things_work.py --mcp --no-token -p 2718

What each flag does

Why pin the port

marimo uses 2718 by default, but if that port is busy it silently picks another one — and then the address you registered points nowhere.2 Since the registered URL is hard-coded to 2718, pin marimo to it with -p 2718. That forces marimo to either use 2718 or fail loudly at startup, instead of drifting to a different port and leaving /mcp mysteriously "disconnected."

Keep them in sync The launch flag and the registered URL must name the same port. If you ever change one to a new port, change both.

The session loop

Every working session follows the same three beats. The endpoint disappears when marimo closes, so this repeats each time.1
